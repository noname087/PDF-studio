# Thai PDF Studio

เว็บแอปสำหรับ **อ่าน / แก้ไขข้อความภาษาไทย / รวมไฟล์ / แยกไฟล์ PDF** โดยสระและวรรณยุกต์ไม่ลอย ไม่ซ้อนทับกัน

ใช้ได้ 2 แบบ: รันในเครื่องตัวเอง (ไฟล์ไม่ออกจากเครื่อง) หรือเอาขึ้นเว็บให้คนอื่นใช้ (ดูหัวข้อ [เอาขึ้นเว็บ](#เอาขึ้นเว็บ))

## ความสามารถ

| เมนู | ทำอะไรได้ |
|---|---|
| ✎ แก้ข้อความ | คลิกบรรทัดใดก็ได้ แล้วพิมพ์ข้อความใหม่ เลือกฟอนต์ ขนาด สี ตัวหนา/เอียง จัดชิดซ้าย/กลาง/ขวา |
| ＋ เพิ่มข้อความ | คลิกตรงไหนของหน้าก็ได้ แล้ววางข้อความใหม่ (ใช้กับ PDF ที่เป็นภาพสแกนได้ด้วย) |
| ⌫ ลบพื้นที่ | ลากกรอบเพื่อลบข้อความออกจริง (ภาพและเส้นตารางยังอยู่) |
| รวมไฟล์ | เลือกหลายไฟล์ จัดลำดับ แล้วรวมเป็นไฟล์เดียว |
| แยกไฟล์ | ตามช่วงหน้า เช่น `1-3, 5, 8-` / ทุก ๆ N หน้า / ทีละหน้า (ได้ไฟล์ .zip) |
| จัดการหน้า | หมุน ลบ เลื่อนลำดับหน้า (ที่ภาพย่อด้านซ้าย) |
| ดึงข้อความ | บันทึกข้อความทั้งเล่มเป็น .txt (แก้อักขระเพี้ยนให้แล้ว) |
| ย้อนกลับ | Ctrl+Z ย้อนได้ 30 ขั้น |

## วิธีติดตั้งและใช้งาน

ต้องมี Python 3.10 ขึ้นไป

**Windows**: ดับเบิลคลิก `run.bat`

**macOS / Linux**:

```bash
./run.sh
```

แล้วเปิดเบราว์เซอร์ไปที่ http://localhost:8000

หรือรันเอง:

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```

## เอาขึ้นเว็บ

repo นี้มี `Dockerfile` และ `render.yaml` พร้อมแล้ว วิธีที่ง่ายที่สุดคือ **Render.com** (มีแบบฟรี)

1. สมัคร https://render.com ด้วยบัญชี GitHub
2. กด **New +** → **Blueprint**
3. เลือก repo `PDF-studio` → กด **Apply**
4. รอ build ประมาณ 3–5 นาที จะได้ลิงก์แบบ `https://pdf-studio-xxxx.onrender.com`

หลังจากนั้นทุกครั้งที่ push ขึ้น branch `main` Render จะอัปเดตเว็บให้เอง

**แบบฟรีของ Render**: เว็บจะหลับถ้าไม่มีคนใช้ 15 นาที เปิดครั้งแรกหลังหลับต้องรอ 30–60 วินาที
และเอกสารที่เปิดค้างไว้จะหายเมื่อเว็บหลับ (ฟอนต์ที่อัปโหลดก็หายด้วย) ถ้าใช้จริงจังแนะนำแผน Starter (7 ดอลลาร์/เดือน)

ใช้ที่อื่นก็ได้ เพราะเป็น Docker image ธรรมดา เช่น Google Cloud Run, Fly.io, Railway, หรือ VPS:

```bash
docker build -t pdf-studio .
docker run -p 8000:8000 pdf-studio
```

> ต้องรัน **1 process เท่านั้น** (อย่าเพิ่ม workers หรือ scale หลาย instance) เพราะเอกสารที่เปิดอยู่เก็บในหน่วยความจำของ process
> ถ้าใช้ Cloud Run ให้ตั้ง max instances = 1 และเปิด session affinity

### ตั้งค่า (environment variables)

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `MAX_UPLOAD_MB` | 30 | ขนาดไฟล์ PDF สูงสุดต่อไฟล์ |
| `MAX_MERGE_MB` | 80 | ขนาดรวมสูงสุดตอนรวมไฟล์ |
| `MAX_MERGE_FILES` | 20 | จำนวนไฟล์สูงสุดที่รวมได้ครั้งเดียว |
| `MAX_PAGES` | 300 | จำนวนหน้าสูงสุดต่อไฟล์ |
| `MAX_DOCS` | 20 | จำนวนเอกสารที่เปิดค้างในหน่วยความจำ (เกินแล้วลบอันที่ไม่ได้ใช้นานสุด) |
| `DOC_TTL_MINUTES` | 60 | ลบเอกสารเมื่อไม่มีคนใช้นานเท่านี้ |
| `MAX_UNDO` / `MAX_UNDO_MB` | 15 / 60 | ประวัติย้อนกลับต่อเอกสาร |
| `MAX_FONT_MB` | 15 | ขนาดไฟล์ฟอนต์ที่อัปโหลดได้ |
| `FONT_TTL_DAYS` | 7 | ลบฟอนต์ที่ผู้ใช้อัปโหลดหลังจากนี้ |
| `SOURCE_URL` | ลิงก์ repo นี้ | ลิงก์ "ซอร์สโค้ด" ที่แสดงในหน้าเว็บ (AGPL กำหนด) |
| `PORT` | 8000 | พอร์ตที่เซิร์ฟเวอร์ฟัง (Render ตั้งให้เอง) |

แผนฟรี (RAM 512 MB) ใช้ค่าเริ่มต้นได้ ถ้าเครื่องใหญ่ขึ้นค่อยเพิ่ม `MAX_DOCS` และ `MAX_UPLOAD_MB`

### ความปลอดภัยและความเป็นส่วนตัว

- ไฟล์ PDF อยู่ในหน่วยความจำเท่านั้น ไม่เขียนลงดิสก์ และถูกลบอัตโนมัติตาม `DOC_TTL_MINUTES`
- รหัสเอกสารเป็นเลขสุ่ม 128 บิต เดาไม่ได้
- ฟอนต์ที่อัปโหลดแยกตามเบราว์เซอร์ คนอื่นไม่เห็น
- ยังไม่มีระบบล็อกอินและไม่มีการจำกัดจำนวนครั้งที่เรียกใช้ ถ้าเปิดสาธารณะแล้วมีคนใช้เยอะผิดปกติ
  แนะนำให้วาง Cloudflare (ฟรี) ไว้ข้างหน้า

## ทำไมสระไม่ลอย

ปัญหาสระลอยเกิดจากโปรแกรมวาดตัวอักษรทีละตัวโดยไม่ "จัดรูป" (shaping) ภาษาไทย
แอปนี้วาดข้อความผ่านเอนจิน HTML ของ PyMuPDF ซึ่งใช้ **HarfBuzz** อ่านกฎ GSUB/GPOS ในฟอนต์
จึงวางสระบน สระล่าง วรรณยุกต์ ได้ถูกตำแหน่ง เช่น `ปั้น` `ผู้ใหญ่` `น้ำ` `ฎีกา` `ญาติ`

นอกจากนี้ยังแก้ปัญหาที่พบบ่อยกับ PDF ภาษาไทยอีก 3 อย่าง:

1. **ข้อความที่ดึงออกมาเพี้ยน** – PDF ที่สร้างจาก Word มักเก็บวรรณยุกต์เป็นอักขระพิเศษ (U+F700–F71A)
   แอปแปลงกลับเป็นอักษรไทยมาตรฐานให้ก่อนแสดงในช่องแก้ไข (`app/thai.py`)
2. **คัดลอกข้อความที่แก้แล้วได้ "�"** – ฟอนต์ไทยสลับรูปวรรณยุกต์ (เช่น ไม้เอกตัวต่ำ)
   แอปสร้างตาราง ToUnicode ใหม่จากกฎในฟอนต์ ข้อความที่แก้จึงค้นหาและคัดลอกได้ถูกต้อง
3. **ข้อความเดิมยังซ่อนอยู่ใต้ข้อความใหม่** – แอปลบตัวอักษรเดิมออกจากไฟล์จริง (redaction)
   ไม่ใช่แค่เอากล่องขาวไปปิด พื้นหลังสี ภาพ และเส้นตารางยังอยู่ครบ

ข้อความใหม่จะวางบนเส้นฐาน (baseline) เดียวกับบรรทัดเดิม และแอปจะเลือกฟอนต์ที่คล้ายฟอนต์เดิมให้อัตโนมัติ

## ฟอนต์

มีฟอนต์มาให้ในตัว: **TH Sarabun New**, **Sarabun**, **Noto Sans Thai**, **Noto Serif Thai**

อยากใช้ฟอนต์อื่น (เช่น TH SarabunPSK, Angsana New) กดปุ่ม **+ ฟอนต์** ในหน้าต่างแก้ไข แล้วเลือกไฟล์ .ttf/.otf
ฟอนต์จะถูกเก็บไว้ที่ `app/fonts/user/<รหัสเบราว์เซอร์>/` แยกของใครของมัน (สูงสุด 10 ไฟล์ต่อคน)

## ข้อจำกัด

- **PDF ที่เป็นภาพสแกน** ไม่มีตัวอักษรให้แก้ ใช้ "ลบพื้นที่" + "ทาสีพื้นทับ" แล้ว "เพิ่มข้อความ" แทนได้ (ยังไม่มี OCR)
- ถ้า PDF ต้นฉบับไม่ได้เก็บข้อมูลว่ารูปตัวอักษรไหนคือตัวอะไร (ไม่มี ToUnicode)
  ข้อความเดิมในช่องแก้ไขอาจเป็นอักษรเพี้ยน ให้พิมพ์ใหม่ทั้งบรรทัด ผลลัพธ์ที่ได้จะถูกต้อง
- แก้ได้ทีละบรรทัด ถ้าบรรทัดเดิมมีหลายสไตล์ปนกัน (เช่น ตัวหนาบางคำ) บรรทัดใหม่จะใช้สไตล์เดียว
- ข้อความแนวตั้ง/เอียงยังแก้ไม่ได้
- ฟอนต์ในไฟล์ PDF ต้นฉบับมักถูกตัดเหลือเฉพาะตัวที่ใช้ แอปจึงใช้ฟอนต์ของตัวเองแทน หน้าตาอาจต่างจากเดิมเล็กน้อย
  (ถ้ามีไฟล์ฟอนต์ตัวเดียวกับต้นฉบับ ให้เพิ่มด้วยปุ่ม **+ ฟอนต์**)

## โครงสร้างโค้ด

```
app/
  main.py         เว็บเซิร์ฟเวอร์ (FastAPI), API ทั้งหมด, ขีดจำกัด และการลบไฟล์อัตโนมัติ
  pdf_engine.py   อ่าน/แก้ข้อความ, รวม, แยก, แก้ ToUnicode
  thai.py         ทำความสะอาดข้อความไทยที่ดึงจาก PDF
  static/         หน้าเว็บ (HTML/CSS/JS ล้วน ไม่ต้อง build)
  fonts/          ฟอนต์ไทยที่มากับแอป
Dockerfile        สำหรับเอาขึ้นเว็บ
render.yaml       ตั้งค่าสำหรับ Render.com
tests/
  test_engine.py  ทดสอบ: python tests/test_engine.py
  make_samples.py สร้างไฟล์ PDF ตัวอย่างใน samples/
```
